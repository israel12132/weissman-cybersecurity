Subprocessors & data-flow disclosures

Effective: 2026-06-09 · Maintained per GDPR Art. 28(2) / DPA Annex III

Weissman engages the following sub-processors and external data sources for the Cloud SaaS edition. Self-hosted installations control all of these independently and may omit any of them.

1. Infrastructure sub-processors

Vendor Purpose Data processed Region
AWS Primary IaaS (EC2, RDS, S3, KMS) All tenant data (encrypted at rest with KMS) EU-West-1 (default), US-East-1, AP-Southeast-2

2. Threat-intelligence data sources (outbound only)

These public feeds are pulled to enrich findings; we send the CVE identifier as the only request payload. No customer-identifying data is transmitted.

Source Cadence Data exchanged
cisa.gov — KEV catalog Every 6 hours Outbound: GET the full known_exploited_vulnerabilities.json (~1.5 MB). No identifiers sent.
api.first.org — EPSS Every 12 hours + on-demand Outbound: GET ?cve=CVE-NNNN-NNNN[,…]. Only CVE IDs sent; no tenant or asset data.
nvd.nist.gov — NVD CVE feeds Daily Outbound: GET feed deltas. No customer data sent.
osv.dev On-demand Outbound: package name + version lookups. No customer data sent.
api.github.com — Advisories Periodic Outbound: GHSA lookups. Bearer token from operator env.

3. Optional LLM providers (operator-configured)

When the Council RAG, NL→SQL planner, or generative-fuzz engines are used, the operator configures an OpenAI-compatible inference endpoint. Possible choices and their data implications:

  • OpenAI — production endpoints (api.openai.com/v1/chat/completions, /v1/embeddings). Prompts may include scan target URLs, engine names, and (for NL→SQL) the user's natural-language question. Subject to OpenAI's data-handling policy. Opt-out by setting a self-hosted base URL.
  • Self-hosted vLLM / Ollama — runs on customer or operator infrastructure; no third-party transit. This is the recommended posture for regulated workloads.
  • Azure OpenAI / Together / Anthropic / other — any OpenAI-protocol-compatible server works. Operator's choice.

The platform never sends raw vulnerability evidence, customer credentials, or PII to an LLM by default. Code snippets analysed by the predictive_analyzer engine are truncated to 4 000 chars and intended for code-review prompts; operators using public LLMs should only enable predictive analysis on non-sensitive repos.

4. Notification of changes

New sub-processors are announced at least 30 days in advance via email to the billing contact and via banner notice in the cockpit. Customers may object; if objection cannot be resolved, the customer may terminate the affected service per the DPA.
