Data Processing Addendum (DPA)

Effective: 2026-06-03 · Version 1.0 · Incorporates EU SCCs (2021/914)

This Data Processing Addendum ("DPA") forms part of the Terms of Service between you ("Controller") and Weissman Cybersecurity Ltd. ("Processor", "Weissman") when Weissman processes Personal Data on Controller's behalf within the European Economic Area, the United Kingdom, Switzerland, or any jurisdiction with equivalent data protection law.

1. Definitions

"GDPR" means Regulation (EU) 2016/679. "Personal Data" has the meaning in GDPR Art. 4(1). "SCCs" means the EU Standard Contractual Clauses (Commission Decision 2021/914/EU). Other capitalised terms are defined in the Terms.

2. Subject matter & duration

Weissman processes Personal Data submitted by Controller to the Service, for the duration of the Agreement and the retention windows in the Privacy Policy.

3. Nature & purpose

Continuous offensive security scanning, vulnerability management, audit logging, and automated remediation of Controller's authorised Targets.

4. Categories of data subjects

  • Controller's authorised personnel using the Service (admins, analysts, viewers).
  • Endpoint owners whose devices run the Weissman agent (with Controller's authorisation).
  • Identities discovered during scans (e.g. exposed email addresses in leak detection).

5. Categories of personal data

  • Contact data: email, name (if provided).
  • Account data: hashed password, MFA seed (encrypted), role, tenant_id.
  • Operational data: IP address, user-agent, audit log entries.
  • Scan-derived data: any Personal Data inadvertently present in scanned URLs / responses / SBOMs / GitHub commits.

6. Processor obligations

  • (a) Instructions. Process Personal Data only on Controller's documented instructions (including via the Service configuration).
  • (b) Confidentiality. Bind personnel to confidentiality.
  • (c) Security. Implement technical & organisational measures in Annex II.
  • (d) Sub-processors. Engage only sub-processors that meet equivalent obligations; current list at /subprocessors.html; 30-day notice for additions, Controller may object.
  • (e) Assistance. Assist with data-subject requests, DPIAs, breach notifications.
  • (f) Breach. Notify without undue delay (target: 72 hours) of a Personal Data breach.
  • (g) Deletion / return. On termination, delete or return Personal Data (Controller's choice), subject to legal retention.
  • (h) Audit. Make available all information needed to demonstrate compliance. Annual independent audit reports available under NDA.

7. International transfers

For transfers outside the EEA / UK / Switzerland, the parties incorporate the SCCs (Module 2: Controller-to-Processor) by reference. Annex I, II, III to the SCCs are populated as follows:

  • Annex I.A — List of Parties: Controller as identified in the order form; Processor: Weissman Cybersecurity Ltd., Tel Aviv-Yafo, Israel.
  • Annex I.B — As Sections 4–5 above.
  • Annex I.C — Competent supervisory authority: where the Controller is established.
  • Annex II — Technical & Organisational Measures: see below.
  • Annex III — Sub-processors: see /subprocessors.html.

8. Annex II — Technical & Organisational Measures

  • Encryption. TLS 1.2+ in transit (HSTS, modern ciphers). AES-256 / KMS at rest. Application-level encryption for MFA seeds.
  • Access control. RBAC (viewer / analyst / operator / admin / ceo); enforced via JWT + Postgres Row-Level Security. Production access requires hardware-key SSH.
  • MFA. TOTP enforced for all admin roles; tenant-wide MFA-required policy supported.
  • Audit logging. Immutable append-only audit_logs table; all auth events, scan launches, config changes recorded with actor + IP.
  • Tenant isolation. Postgres RLS forced on every multi-tenant table; cross-tenant queries are physically blocked by policy.
  • Network. Backend not exposed; only the gateway listens publicly. WAF + rate limiting at the edge.
  • Vulnerability management. Weissman runs its own engines against itself (self-scan) every cycle; automated PR remediation; weekly dependency scanning.
  • Backup. Encrypted daily backups, 30-day retention, restore-tested quarterly.
  • Incident response. 24×7 on-call; documented runbooks; breach notification ≤ 72 hours.
  • Personnel. All staff sign NDAs; background-checked; mandatory annual security training.

9. Signing

This DPA is automatically incorporated upon your acceptance of the Terms of Service. For enterprise contracts requiring a separately signed DPA, request one from legal@weissman.io.
